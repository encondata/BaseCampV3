# Nav Preferences Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Per-user nav preferences — sidebar mode (expanded / rail / hidden, with toggle + Ctrl/⌘+B), sidebar background color, and sidebar text size — settable from Settings › Appearance and applied on the shell.

**Architecture:** Three new keys on the existing `UiPreferences` JSONB (no migration). `lib/settings.ts` stamps them on `.portal-shell` as data attributes / CSS variables; `portal-theme.css`/`chrome.css` nav rules read the variables with today's values as fallbacks. AppShell's nav markup is extracted to `NavPanel` (used docked and as the hidden-mode overlay); AppShell owns mode state, the flyout, the overlay, the toggle, and the shortcut; Topbar renders a `leading` slot for the hamburger.

**Tech Stack:** FastAPI/pydantic (api), React 18 + TS + Vitest (portal), CSS variables.

## Global Constraints

- Spec: `docs/superpowers/specs/2026-09-10-nav-prefs-design.md` — read it first; every value below comes from it.
- Preference keys/values exactly: `nav_mode` ∈ expanded|rail|hidden (default expanded); `nav_bg` = "default" | `#rrggbb` (default "default"); `nav_size` ∈ small|default|large|xlarge (default default). `--nav-scale`: 0.9 / 1 / 1.12 / 1.25.
- `NAV_BACKGROUNDS`: Slate #1f2937, Navy #0f2a4a, Forest #0f2e25, Plum #2b1a3d, Charcoal #18181b, Paper #f3f4f6.
- Widths: expanded 248px, rail 64px, hidden 0; mobile breakpoint `max-width: 900px` behaves as hidden.
- Typography guardrail (`portal/src/styles/listTypography.test.ts`): nav selectors already allowlisted may change their declarations to `calc(<px> * var(--nav-scale, 1))`; NEW selectors must not declare font-size/family/weight/line-height/min-height; no new `listTypography.allow.json` entries; no raw native `<select>` in Settings (use the existing `seg-mini` pills and `accent-sw` swatches).

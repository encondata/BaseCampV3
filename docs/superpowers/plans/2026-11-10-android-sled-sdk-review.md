# Android Sled SDK Review Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the Zebra RFD40 sled work on a phone with no DataWedge: a live RFID / Barcode / Both trigger switch, sled barcodes on every scan screen delivered once, link loss noticed and reconnected within set limits, every RFID-tab option doing what the SDK does, and a build ready for a hardware session.

**Architecture:** T1 writes and freezes the contract: the `RfidReader` interface with a KDoc paragraph per member, the pure types in `core/rfid`, every operator sentence in `SledWords`, and a finished `FakeRfidReader`. Track A then rewrites the Zebra adapter on one never-interrupted worker thread, with pure helpers in `core/rfid` and a scanner engine behind a vendor-free interface. Track B rebuilds the controller (link gate, reconnect, job queue), the app wiring (scan guard, receivers, display effect) and the screens against the fake. The tracks touch disjoint files and meet at M1.

**Tech Stack:** Kotlin, Jetpack Compose, kotlinx.coroutines, DataStore, Zebra RFID API3 2.0.5.292 (bundles scanner SDK 2.6.9.4), JUnit 4, Robolectric (sdk 34), Compose UI test.

A connect failure is `Result.failure(SledConnectException(failed))` whose `failed` equals the `Failed` state just published (so `message == failed.reason`). A call made in the wrong state returns `Result.failure(SledNotConnected())` with no vendor call; the controller shows nothing for it.

## Review Focus

1. A sled that types a barcode and also sends it through the scanner, with the two copies differing only in surrounding whitespace or a trailing Enter: delivered once, not twice (B3, `SledScanGuardTest.copiesDifferingOnlyInSurroundingWhitespaceAreTheSameValue`).
2. The operator taps Sled triggers three times within a second, once during an open sweep: only the latest layout is written when the taps land together (at most one more write when a write is already in flight, and the latest is always last), never while a sweep is open, and that sweep's tags are queued (B2, `RfidJobQueueTest.rapidLayoutChangesWriteTheLatestOnceAndNeverDuringASweep`).
3. The reader switch is turned off while a connect is still in flight: the attempt finishes, the app ends `Disconnected`, nothing retries and no failure sentence shows (B1, `RfidLinkTest.switchingOffDuringAConnectEndsDisconnectedWithNoRetry`).
4. The phone is backgrounded during a reconnect wait and foregrounded before the wait would have ended: the old wait never dials, and exactly one lifecycle connect runs (B1, `RfidReconnectTest.backgroundingDuringAWaitCancelsItAndForegroundDialsOnce`).
5. Bluetooth is turned off while the sled's barcode scanner is `Ready`: the state goes `Off` at once, no vendor call runs while Bluetooth is off, and the cached scanner id is dropped so the next open lists again (A4, `ZebraBarcodeEngineTest.bluetoothTurningOffWhileReadyGoesOffAndDropsTheCachedId`).

# iOS Kiosk Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the native iOS/iPadOS ServerSherpa Kiosk app in `IOS_Kiosk_App/` — a SwiftUI port of the Android kiosk (minus all Zebra code) plus the move-password sign-in and the mockup login screen.

**Architecture:** A layer-by-layer port of `Android_Kiosk_App/app/src/main/java/com/serversherpa/kiosk/`: pure-Swift `Core/` (Foundation only), `Data/` (URLSession, Keychain, SwiftData, UserDefaults), `Input/` (scan bus, AVFoundation camera), `UI/` (SwiftUI). One manually wired `AppContainer`. Behavior, copy and constants come from the named Android file; its unit tests are ported with it.

**Tech Stack:** Swift 5 language mode, SwiftUI, Observation, SwiftData, URLSession, Security (Keychain), AVFoundation, Core Image, AVAudioEngine, GameController, Swift Testing. Xcode 26.1.1. No third-party packages.

**Spec:** `docs/superpowers/specs/2026-09-30-ios-kiosk-design.md` — read it before your task; it is the source of truth for anything this plan does not spell out.

## Global Constraints

- **Porting rule.** When a task says "port `X.kt`", open that Android file (under `Android_Kiosk_App/app/src/main/java/com/serversherpa/kiosk/`) and its test (under `Android_Kiosk_App/app/src/test/java/com/serversherpa/kiosk/`), and reproduce the behavior, user-facing copy, constants and test cases exactly, in idiomatic Swift, using the Swift names given in the task's **Interfaces** block. Every Android test case in the named test file becomes a Swift Testing `@Test` (same inputs, same expected values). Do not port anything RFID-reader-related (`core/rfid/*`, `input/rfid/*`, `input/datawedge/*`, `RfidReadPanel`, `RfidPanel`, the Admin region section, `DeveloperRfidBurst`).
- Minimum OS **iOS/iPadOS 18.0**. iPad first (all four orientations), iPhone supported (portrait + landscape).
- **No third-party dependencies.** No Swift packages.
- `Core/` imports **only** `Foundation` (enforced by `CorePurityTests`).
- `SWIFT_DEFAULT_ACTOR_ISOLATION = nonisolated`; mark `@Observable` app state, view models and anything touching UIKit `@MainActor` explicitly.
- JSON field names are the server's snake_case: use explicit `CodingKeys` (never `keyDecodingStrategy`), so a Swift property `assetId` maps to `"asset_id"`. Decoding ignores unknown keys (Codable default) and every Android field with a default value is decoded with `decodeIfPresent ?? default`.
- UserDefaults keys are the web's `ss.kiosk.*` names from Android `data/prefs/KioskPrefs.kt` (`ss.kiosk.setupState`, `ss.kiosk.setup`, `ss.kiosk.appearance`, `ss.kiosk.sound`, `ss.kiosk.devMode`, `ss.kiosk.apiUrl`, `ss.kiosk.portalUrl`, `ss.kiosk.name`, checkpoint keys from `CheckpointId`), plus `ss.kiosk.cameraPosition`.
- Heartbeat `mode` is `"ios"`. Serial prefix `kiosk-ios-`.
- Default URLs: API `https://api.dev.serversherpa.com` (Debug) / `https://api.serversherpa.com` (Release); portal `https://portal.dev.serversherpa.com` (both).
- American English in all copy and comments (color, canceled, etc.). Copy strings are copied from the Android/web source, not reworded.
- The project uses Xcode synchronized folders: creating a file under `ServerSherpa Kiosk/` or `ServerSherpa KioskTests/` adds it to the target. **Never hand-edit `project.pbxproj`** except for the build settings in Task 1.
- Paths below are relative to `IOS_Kiosk_App/ServerSherpa Kiosk/` unless they start with `Android_Kiosk_App/`, `docs/`, `portal/` or `IOS_Kiosk_App/`. `APP` = `ServerSherpa Kiosk/` (the app source folder), `TESTS` = `ServerSherpa KioskTests/`.

# Wiki Phase 3 (reach) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Public share links, portal/kiosk help links, analytics (views, helpfulness, failed searches,
stale pages) and export (PDF, .docx, Markdown, folder .zip) for the wiki.

**Architecture:** Migration 0076 adds the tables; each feature is one end-to-end task (API + worker
where needed + UI). Export renders HTML through the wiki server's `/internal/render` (the only
JSON→HTML authority) and converts with WeasyPrint (PDF) or LibreOffice (.docx) in the wiki worker.

**Spec:** `docs/superpowers/specs/2026-09-25-wiki-design.md` §8. Conventions: Phase 1 plan's Global Constraints; Phase 2 plan's notification service (`wiki/notify.py`).

## Global Constraints

- Phase 1 and Phase 2 Global Constraints apply. Migration **0076** (`down_revision = "0075"`).
- Space setting `allow_public_links: bool` (default false) added in `wiki/space_settings.py` only.
- Public (unauthenticated) routes live under `/wiki/public/*`, use `deps.rate_limit_ip` (read how it is applied elsewhere, e.g. kiosk pairing), return only PUBLISHED content, never internal ids beyond the node id needed for asset lookups, never presigned URLs valid > 10 minutes, and 404 for every failure mode (unknown, revoked, expired, space setting off, node deleted, page unpublished).
- Share tokens: 32 bytes urlsafe random; only the sha256 hash is stored; the token is shown once on creation.
- New settings: `wiki_render_url: str = "http://localhost:5177"` (the wiki server, used by the worker for `/internal/render` with `X-Wiki-Service-Token`).
- Export files go to `wiki/exports/<job_id>/<name>`; presigned download URL lifetime 24 h; exports purged after 7 days by the worker's retention sweep.
- Analytics retention: page views 365 days, search log 90 days (worker daily sweep).
- Portal and kiosk changes must keep their guardrail tests green (portal `npm --prefix portal test`, kiosk `npm --prefix kiosk test`); the kiosk may only import React-free portal modules.

### Task 1: Schema 0076, models, settings

Tables: `wiki_share_links(id, node_id fk nodes cascade, token_hash text unique, created_by, created_at, expires_at null, revoked_at null, view_count int default 0, last_viewed_at)`; `wiki_help_links(id, context text unique (1–300), node_id fk nodes cascade, created_by, created_at)`; `wiki_page_views(node_id fk cascade, person_id fk people cascade, viewed_on date, count int, pk(node_id, person_id, viewed_on))`; `wiki_feedback(node_id fk cascade, person_id fk cascade, helpful bool, comment text null (≤2000), updated_at, pk(node_id, person_id))`; `wiki_search_log(id bigint identity, person_id fk set null, query text, result_count int, at timestamptz default now())` + index `(at)`. `wiki_jobs.kind` CHECK gains `'export'`, `'retention'`. Settings `wiki_render_url`; space setting `allow_public_links`. conftest TRUNCATE list. Tests: tables/constraints, setting validation.

### Task 2: Public share links (API + UI)

API: `POST /wiki/nodes/{id}/share-links {expires_in_days: 1|7|30|90|null}` (manage on node; page or file only → 422 `bad_kind`; space must allow → 422 `links_disabled`) → `{id, url: f"{wiki_origin}/p/{token}", expires_at}` (token only here); `GET /wiki/nodes/{id}/share-links` (manage) → list without tokens; `DELETE /wiki/share-links/{id}` (manage or creator) → revoke; `GET /wiki/share-links` (wiki admin) all links. Public: `GET /wiki/public/{token}` → page `{kind:'page', title, content_json, published_at, asset_urls: {assetId: url}}` (assets referenced by the published content only) or file `{kind:'file', title, filename, content_type, size_bytes, url (inline allowlist rules from Phase 1, else attachment)}`; increments view_count/last_viewed_at; PageLinks inside are returned as-is (the SPA renders them as plain text).
UI: ShareDialog (page/file ⋯ "Share…", manage only; shows links, create with expiry select, copy once, revoke); public route `/p/:token` OUTSIDE RequireAuth with a slim header ("Shared from ServerSherpa Wiki") and ReadOnlyDoc in a public mode where pageLink renders as plain text and images use `asset_urls`; admin page gains "Public links" section.
Tests: API matrix (rights, disabled space, expiry, revoked, deleted, unpublished → 404; hash-only storage; rate limit hook present); SPA public view renders without a session and never calls authenticated endpoints.

### Task 3: Help links (API + wiki UI + portal + kiosk)

API: `GET /wiki/help?context=portal:/bulk/time` → longest-prefix match on contexts (normalize: lowercase, strip trailing slash, ids in paths replaced by `:id` using a UUID/number regex before matching) → `{node_id, title, url}` if the caller can view the node, else 404; `GET/POST/PATCH/DELETE /wiki/help-links` (wiki admin) with context validation (`^(portal|kiosk):/[a-z0-9/_:-]*$`).
Wiki UI: admin "Help links" page (list, add with a context field + page picker, edit, delete); page ⋯ "Use as help for…" (admins) opening the same form prefilled with the page.
Portal: a "?" help button in the top bar (find `portal/src/components/Topbar.tsx`); on click calls `GET /wiki/help?context=portal:<pathname>` → opens the guide in a new tab at the returned url, or a small popover "No guide for this page yet" (+ "Link a guide" for wiki admins → opens `${wikiOrigin()}/admin/help-links?context=…`). Hidden without `wiki:view`.
Kiosk: same button in the kiosk shell header (online only; `kiosk:` contexts from `location.pathname`), using React-free portal helpers only.
Tests: matching rules; permissions; portal and kiosk button behavior (mocked fetch).

### Task 4: Analytics (API + worker + UI)

API: `POST /wiki/nodes/{id}/view` (view; pages/files; upsert today's row count+1; 204); `PUT /wiki/pages/{id}/feedback {helpful, comment?}` (view; published pages); `GET /wiki/pages/{id}/feedback/mine`; search route logs `(person, query, result_count)`; `GET /wiki/analytics?space=&days=30` (wiki admin: all; space managers: their spaces, `space` required for them) → `{top_pages:[{node, views, viewers}], views_by_day:[{day, views}], helpfulness:[{node, yes, no, pct}], recent_no_comments:[{node, comment, at}], failed_searches:[{query, count, last_at}], stale_pages:[{node, updated_at}] (not updated in 12 months), overdue_reviews:[…]}`. Worker `retention` daily: delete old views/search log/exports (7 days).
UI: PageView/FileView record a view once per mount (debounced; not for the author's own edit sessions); "Was this page helpful? Yes / No" footer on published pages with an optional comment box on No; AnalyticsPage (`/analytics`, visible to admins and space managers) using portal list styles and simple SVG bars (reuse the portal's chart primitives only if React-free/allowlistable; else small local SVG components).
Tests: API aggregation + permissions + retention; UI footer + analytics rendering.

### Task 5: Export (API + worker + UI)

API: `POST /wiki/exports {node_id, format: 'pdf'|'docx'|'md'|'zip', zip_format?: 'pdf'|'docx'|'md'}` (view on node; `zip` for folders/spaces-home/pages with children; pages allow pdf/docx/md; files → 422 use Download) → `{job_id}` (queues `export`); `GET /wiki/exports/{job_id}` (requester only) → `{status, url|null, error|null}`.
Worker `export`: for each page in scope that the REQUESTER can view (AccessIndex from the requester's principal; view-only → published content; editors → published too — exports are of published content only; never-published pages skipped with a note in a `_skipped.txt` for zips): JSON → HTML via `POST {wiki_render_url}/internal/render {doc}` (service token) → wrap in a print template (title, breadcrumbs, published date, portal CSS tokens inlined, `data-text-align` styling, images resolved to presigned URLs fetched and inlined as data URIs); PDF via WeasyPrint; docx via `soffice --convert-to docx` from the HTML; Markdown via a Python JSON→Markdown serializer in `wiki/markdown.py` (headings, lists, task lists, tables (GFM), code, callouts as blockquotes with a bold label, images as `![alt](assets/<file>)` with the files included in zips, page links as relative links inside zips / titles for single pages). Zips mirror the tree with sanitized names and include files (current versions) the requester can view. Upload the result, notify the requester (`wiki_export_ready` kind via `wiki/notify.py`, link to the presigned URL is NOT stored — link to `${wiki_origin}/exports/<job_id>` which re-presigns), mark done.
UI: page/folder ⋯ "Export…" dialog (format choice; zip options for folders) → progress (poll every 2 s) → download button; route `/exports/:jobId` for inbox links.
Tests: markdown serializer table-driven; export permission filtering; worker pipeline with render/WeasyPrint/soffice faked + one real WeasyPrint PDF test skipped when unavailable; UI dialog flow.

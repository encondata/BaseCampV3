# Timesheet report — design

Date: 2026-10-06. Branch `timesheet-report`. To-Do #14 "Make the timesheet a
real report"; Feature Parity row 277 / Gaps row 81 "Timesheet report — hours
worked by person and job over a date range, as Excel or PDF" (Partial today:
the Timesheet screen only exports its visible rows to CSV). V2 reference:
`BaseCampV2-reference/api/reports/time_sheets_report.py` + `portal-v4/src/pages/TimeSheets.jsx`.
Jimmy asked for no input: existing UI/UX and my recommendations. Decisions
below are mine.

## What it is

A new report type `timesheet` on the existing reports framework (Reports ›
Available › **Timesheet**, a system definition), generated by the report
worker as **Excel** or **PDF**, over a date range with optional Person, Job
and Site filters. It has V2's two views — a **day view** (one row per person
per day) and a **punch view** (every entry) — plus a summary, and V3
**verification flags** on every entry.

## Run options (stored in `report_runs.options`)

| key | values | default |
|---|---|---|
| `from`, `to` | `YYYY-MM-DD`, `from <= to`, span ≤ 366 days | required |
| `person_id` | person uuid or absent | everyone |
| `site_id` | site uuid or absent | all sites |
| `statuses` | non-empty subset of `approved`, `pending`, `rejected`, `open` | `["approved","pending"]` |
| `views` | non-empty subset of `day`, `punch` | `["day","punch"]` |
| `format` | `xlsx` / `pdf` | `xlsx` |

The **Job** filter is the run's own `initiative_id` (optional), so History's
Initiative column shows it. A timesheet is **never** saved to the job's
Files (no Attachment row): Files are readable with `attachments:view`,
which would expose hours to people without `time:view`. The file lives only
in the report run (History download, gated below). `create_run` accepts a
`timesheet` run with no initiative.

Definition options (Edit on the Available tab): `default_format`
(`xlsx`), `default_views` (`["day","punch"]`), `default_statuses`
(`["approved","pending"]`). A run's own keys win; missing ones fall back to
the definition's, then these.

## Data rules

- Entries: `time_entries` matching the filters and statuses, unarchived
  people included (history), joined to person, job and site names
  (`Person.display_name`), approver name.
- **Day and time zone:** each entry is placed on its local date, in its
  site's `timezone` when the site has one, else `report_timezone()`
  (America/New_York). Clock times print in that zone with its abbreviation
  (e.g. `07:02 EDT`). The date range is inclusive on those local dates.
- **Worked minutes** = `services.timeclock.worked_minutes(entry)` (0 for an
  open entry). Hours print as `Hh MMm` plus a decimal hours column in Excel
  (2 places) for payroll.
- **Totals** count only `approved` and `pending` (closed) entries, split into
  Approved and Pending. Rejected and open entries appear in the lists when
  their status is chosen but never add to totals.
- **Verification flags** per entry (V2 verified/unverified is the Status
  column; these are V3's checks):
  - `Adjusted` — `adjusted` is true (the reason appears in the punch view).
  - `Manual entry` — `source` is `manual`.
  - `Over 10 h` — worked ≥ 600 minutes; `Over 16 h` — worked ≥ 960 (replaces Over 10 h).
  - `Overlap` — overlaps another of the same person's entries in the result;
    both entries of an overlapping pair are flagged (sorted by clock-in, an
    entry overlaps when it starts before the latest end so far; open entries
    end "now").
  - `Still clocked in` — status `open`.
  A day row's flags are the union of its entries' flags.
- **Days** (summary KPI and preview) = distinct calendar dates with at
  least one listed entry; the By person table's Days = that person's
  distinct dates.
- Limit: more than 20,000 matching entries (counted over the padded UTC
  query window, so a few boundary entries may count) fails the run with
  `too_many_entries` (the preview says so before anyone generates).

## Output

**Excel** (`openpyxl`, sheets in order; bold headers, frozen header row,
autofit ≤ 40):
1. **Summary** — title `Timesheet: {from} to {to}`, lines for Person, Job,
   Site, Statuses, Generated, Time zone note; KPIs Entries, People, Days,
   Approved hours, Pending hours, Flagged entries; then **By person**
   (Person, Days, Entries, Approved, Pending, Total, Flagged) and **By job**
   (Job, People, Entries, Approved, Pending, Total; "No job" row for
   entries without one).
2. **By day** (if `day` in views) — Date, Person, Entries, First in, Last out,
   Worked, Hours, Status, Flags. Status: `Approved` / `Pending` / `Rejected` /
   `On the clock` when all entries share it, else `Mixed`.
3. **Punches** (if `punch` in views) — Date, Person, Job, Site, Clock in,
   Clock out, Break (min), Worked, Hours, Status, Source, Approved by, Flags,
   Adjust reason, Notes.
Rows sort by date, then person (natural), then clock-in.

**PDF** (Jinja + WeasyPrint, Letter landscape, the Move Scan History footer:
`Page N of M`, `Generated … · Document Tracking ID: {run id}`, PDF417
barcode): header block (title, filters, KPI tiles), By person, By job (only
when no Job filter), By day, Punches (per views), "End of Report". Repeating
table headers; status as colored chips (approved green, pending amber,
rejected red, open blue); flags as small chips.

Filenames: `Timesheet - {from} to {to}[ - {person}][ - {job}] - {YYYY-MM-DD HHMM}.xlsx|pdf`
(unsafe characters stripped like Move Scan History).

## Permissions

Reports gates are unchanged (`reports:view` / `reports:add`). Because hours
are time data, the timesheet additionally requires **`time:view`**:
- `POST /reports/runs` for a timesheet → 403 `time_view_required` without it;
- `GET /reports/timesheet/preview` requires both;
- History lists and downloads of `timesheet` runs are hidden from people
  without `time:view` (list filter + 404 on get/download).

## API

- `serversherpa/reports/timesheet/` module: `report_type = "timesheet"`,
  `default_options()`, `validate_options()`, `validate_run_options()`,
  `build(db, run)`; `gather.py` (query + flags + rollups, pure helpers
  testable without the DB where possible), `xlsx.py`, `pdf.py`,
  `templates/timesheet.html`. Registered in `reports/registry.py`.
- Migration **0090** seeds the system definition **Timesheet** (description:
  `Hours worked by person and job over a date range, with a day view, every
  punch and verification flags, as Excel or PDF.`), copying 0054's pattern.
- `GET /reports/timesheet/preview?from&to&person_id&initiative_id&site_id&statuses`
  → `{entries, people, days, approved_minutes, pending_minutes,
  flagged_entries, too_many}` from the same gather.
- Worker inbox body for a timesheet run: `{from} to {to}` plus the person
  and/or job name when filtered.

## Portal

- Reports › Available shows **Timesheet** (TYPE_LABELS `timesheet: 'Timesheet'`).
- Generate modal: a timesheet skips the initiative pick step; its options
  step (`TimesheetOptions`, same `OptionsGrid` / `PreviewCard` /
  `OptionGroup` / `ChoiceCard` idiom as Move Scan History) has:
  - **Dates**: From / To date inputs (house `pf-form`), quick picks **This
    week**, **Last week**, **This month**, **Last month** (mini buttons;
    weeks Monday–Sunday); default **This month** (1st → today).
  - **Filters**: Person (ComboBox, "Everyone"), Job (ComboBox of
    initiatives, "All jobs"), Site (ComboBox, "All sites").
  - **Include**: status ChoiceCards (checkbox) Approved, Pending, Rejected,
    On the clock; defaults from the definition.
  - **Views**: ChoiceCards (checkbox) Day view, Punch view.
  - **Format**: Excel workbook / PDF document; **Notify me** switch.
  - **Preview card**: KPI tiles Entries, People, Days, Approved, Pending,
    Flagged; refreshed (debounced 400 ms) when options change; shows the
    too-many message and disables Generate when `too_many`.
  - Generate disabled until dates are valid and at least one status and one
    view are chosen.
- Edit definition modal: a timesheet branch for the three defaults.
- **Timesheet screen (/people/time)**: a **Timesheet report** mini button in
  the Timesheet toolbar (next to Export), shown with `reports:add` and
  `time:view`, opens the Generate modal on the Timesheet definition with the
  screen's current Person / Job / Site / From / To filters and status pill
  prefilled (pill All → Approved+Pending+Rejected+On the clock; a single
  pill → that status; empty dates → This month).

# Security review 2026-09-13 — fixes

## Scope and method

A code review of the API access model — `require_permission`, `scope_conditions`, the `visible_to` anchors, and `_require_global` — plus the auth lifecycle (`services/auth.py`, `api/deps.py`) and the portal's rendering of stored links, run on 2026-09-13. Every finding was fixed on branch `security-fixes` (worktree off `reports` at `84aee70`) by executing the plan `docs/superpowers/plans/2026-09-13-security-fixes.md`, one task per commit, each fix landing with a regression test that was run red before the change and green after. This document is the audit record: what was wrong, where the fix now lives (`file:line` in the current tree), and which tests lock it in.

## Design decisions worth knowing

- Unarchive is treated as `delete`, symmetric with archive: reversing a soft delete is the same privilege as performing one. This now covers organizations (clients and partners) as well as assets, initiatives, containers and trucks; no seeded role that holds `delete` on any of these loses access, and the client/vendor tier roles (which hold `change` but not `delete` on their own org) lose only the ability to retire it.
- The forced-password-change exemption set is not a superset of the read-only exemption set: `/system/admin` is exempt from read-only mode but not from the forced-change guard.
- System report definitions: rename → 409 `system_definition`; `options` and `description` remain editable (the portal's Edit modal depends on it). `is_system` and `report_type` are not settable through `ReportDefinitionUpdateIn` at all.
- Clock-in/out gate is `time:view` OR role name `worker`, not the `self` scope anchor, because `worker` and `external` share that anchor. `external` and every client/partner role are excluded.
- The WS live tail is exempt from read-only mode on purpose (a tail is a read; `enforce_read_only` only gates mutating methods) but refuses a forced-password-change session with 4403.
- `db_testing_password` has no default; the Testing tab is effectively disabled (503 `db_testing_password_not_configured`) until the env var is set.
- Notes on `initiative`, `person`, `client`, `partner` hosts are internal-only for non-global readers, including the subject of the note. The `Organization.notes` column (the free-text field on the client/partner record itself, distinct from the `/notes` host) follows the same rule: null in list and detail for any non-global actor, like `person_notes` on the worker detail — and, symmetrically, a non-global actor's PATCH that names `notes` (even as null) is refused with 403 `notes_internal` rather than having the field silently dropped.
- Provenance redaction: `site_name`, `device_id`, `actor_name` are null for any non-global actor; the scan/edit facts themselves still return.
- Initiative writes: the scoping loader runs first, then `_require_global`, so a foreign target is 404 and an own target 403 — an actor never learns that an out-of-scope id exists. Moving `_require_global` to the top of a function breaks that property and the matching tests.
- Attachment self-service is avatars only; a self-list without `kind=avatar` goes through the normal permission gate.
- Website validation prepends `https://` only when the input has no scheme at all — a naive `"://" not in v` check would have turned `javascript:alert(1)` into `https://javascript:alert(1)`.

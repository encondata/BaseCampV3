# Kiosk Rolodex: build rulings

Date: 2026-10-22. Merged to main 5bd8492a and pushed. Spec: `2026-10-22-kiosk-rolodex-design.md`. Plan: `../plans/2026-10-22-kiosk-rolodex.md`.

Jimmy said "no more questions", so every decision the plan and spec left open was made during the build and recorded here, each with what it costs if it's wrong. P = pre-flight, S = during the build. S20–S22 are known residuals left for testing.

- Ruling P1: Tasks 5–7 (Android) and 8–10 (iOS) run as two parallel tracks in separate worktrees (`kiosk-rolodex-android`, `kiosk-rolodex-ios`) branched from the Task 4 commit, each sequential, merged back into kiosk-rolodex — the folders are disjoint, and the plan allows it; the skill's no-parallel rule is about one worktree — cost if wrong: a merge conflict in shared files (none expected outside docs).
- Ruling P2: Android EXIF handling may use `androidx.exifinterface` if it is already on the classpath (CameraX pulls it in), else `ImageDecoder`; Robolectric tests may use a synthetic EXIF-6 fixture — "no new libraries" means no new declared dependency — cost if wrong: one dependency line.
- Ruling P3: Android has no top-bar back button, so the phone worker page shows an in-page "‹ Rolodex" control (plus system back via BackHandler) — the plan's test string stays — cost if wrong: a small UI tweak.
- Ruling P1 (revised): the Android and iOS tracks start now, in parallel with the API tasks, from f4b9f9da (worktrees kiosk-rolodex-android, kiosk-rolodex-ios) — Tasks 5/8 depend only on the API contract fixed in the plan, not on API code — cost if wrong: contract drift caught at merge and in the final review.
- Ruling S1: search haystack also includes each field's whole folded whitespace-word before the hyphen split, so "smith-jones" finds Smith-Jones — a hyphenated surname is common on a crew list — cost if wrong: a looser match, harmless. Sent to Task 5 (in progress); carried into the Task 8 fix round.
- Ruling S2: keep validate() strict (a blacklisted worker always needs a note) — the DB CHECK already requires a note for blacklist, and clearing the note of a blacklisted worker would hit that CHECK server-side — cost if wrong: an admin must keep a note on a blacklisted worker, which is the existing rule.
- Ruling S3: status_block_reason = "rank_too_low" for any target the actor can't touch (with or without a login), mirroring apply_profile_update's status guard; edit_block_reason stays login-only like the person guard — spec §4.1 says "untouchable target" — cost if wrong: an account-less high-rank person shows status as locked (the server would refuse anyway).
- Ruling S4: extract the visibility query into one shared helper (worker_edits.visible_workers_query) used by GET /workers and the Rolodex — spec §3.3 says "same query and scope filter", the predicate is security-relevant and two copies drift — cost if wrong: a small refactor of the portal list route (covered by test_workers.py).
- Ruling S5: a real move-password session gets 403 forbidden (rank gate) before move_locked — gate order per spec §4.1; the apps treat any 403 the same — cost if wrong: a different error code in one path, no access change.
- Ruling S6: accept all five — partner_archived matches spec §3.9's picker rule; helper scoping mirrors the portal's two routes (the apps lock Edit entirely when can_edit is false, so the UI stays stricter); duplicates is a POST before a write, so 423 is consistent; the extra matches in 409 are harmless — cost if wrong: small rule tweaks in one route.
- Ruling S7: every successful Rolodex PATCH ensures the WorkerProfile exists, so a worker edited in the Rolodex stays on the Time Clock roster (spec §3.13 upserts them locally) — cost if wrong: a profile row with defaults for workers who had none, which the portal also creates on first profile save.
- Ruling S8: the apps validate email format on the device (edit and New worker forms): non-blank email must look like name@domain.tld with no spaces, copy "Enter a valid email address." (added to validate() on both platforms) — the server's pydantic 422 has no code and would show "Something went wrong." — cost if wrong: a rare valid-but-odd address refused on the device (the admin can clear it).
- Ruling S8 sent to Task 6 (in progress); iOS gets it in Task 9's fix round.
- Ruling S9: bring into Task 9 fix round 1 the review minors that break spec §3.15 (cache must clear on sign-out/session end: write-after-clear race, 403 keeps disk copy, restore() failure skips onSessionEnded) and Review Focus 4 (a failed save after leaving the worker shows no error) — they're spec/focus requirements, not polish — cost if wrong: a slightly larger fix round.
- Ruling S10: a refresh icon satisfies spec §4.2 "pull to refresh (phone) / a refresh action" (PullToRefreshBox is experimental) — cost if wrong: add pull-to-refresh later.
- Ruling S11: the 600dp split is measured on the window, not the padded page (spec §3.10) — folded into fix round 1 — cost if wrong: none.
- Ruling S12: accept locking list selection while the Edit form is open (protects typed changes; iOS blocks leaving mid-save) — cost if wrong: one tap to Cancel first.
- Ruling S13: accept "Create worker" on the New worker crop step (that tap creates the worker; the worker-page retake keeps "Use photo") and the small progress/status labels — cost if wrong: copy tweaks.
- Ruling S14: Android split moves from 600dp to 720dp window width (spec §3.10 revised, commit on kiosk-rolodex) — at 600dp the worker page beside a 360dp list is ~200dp and fields ellipsize — cost if wrong: small tablets in portrait (600-719dp) get the phone layout.
- Ruling S15: list LOAD failure that is network OR 5xx falls back to the cached list read-only with the offline banner on both platforms (iOS behavior; Android aligns) — an editable-looking list after a 5xx invites edits that fail — cost if wrong: the banner says "Offline" during a server outage.
- Ruling S16: Home tile description on both platforms = "Look up workers, edit their details, and take photos." — cost if wrong: copy tweak.
- Ruling S17: POST /duplicates also returns ARCHIVED people matched by email only (is_worker false, matched_on ["email"]) so the apps block Create anyway before the photo; create unchanged — a returning worker's email otherwise fails only at the end — cost if wrong: an archived contact appears in the duplicate sheet.
- Ruling S18: iOS blocks leaving an open Edit form like Android (S12) — prevents silent loss of typed edits — cost if wrong: one tap on Cancel first.
- Ruling S19: one fix wave split into three parallel parts (API in kiosk-rolodex, Android in kiosk-rolodex-android, iOS in kiosk-rolodex-ios, each fast-forwarded to 48bf64a9 inside its own worktree) — the skill asks for ONE fix dispatch; disjoint trees make three parallel dispatches equivalent and faster — cost if wrong: none beyond coordination.
- Ruling S20 (residual, parked): partner_archived / partner_not_found / unknown_level on create/save show the catch-all "Something went wrong. Try again." on both platforms and the pickers aren't reloaded — only reachable when the options went stale mid-flow (company archived elsewhere); the admin picks another value — cost if wrong: a confusing message in a rare case; follow-up: name the field and reload /options.
- Ruling S21 (residual, parked): iOS pops the pushed worker page when the window becomes split even while the photo fullScreenCover is up (iPad divider dragged mid-camera) — may drop or re-present the photo step — rare, needs the live check — cost if wrong: the admin retakes one photo.
- Ruling S22 (residual, parked): iOS 403 forbidden/move_locked on a list load clears the list but leaves the open worker's page (incl. phone/email) on the split view beside "Your account can't use the Rolodex." — only after the admin's rank is lowered mid-session; the data was visible to them a moment earlier — cost if wrong: brief exposure to a just-demoted admin; follow-up: also clear selectedId/detail on 403.

# Generate Labels — V3 port of V2's `/labels/generate`, as a worker

**Date:** 2026-09-11 · **Status:** approved by standing instruction (copy all V2 functionality, V3 UI/UX; label generation becomes a worker process so other surfaces can invoke it later) · **Branch:** `generate-labels`

## Purpose

V2's Generate Labels page picks a move and one or more label types, then a background job renders a ZPL label per asset from the active template for each type (skipping assets that already have one unless overwriting), reporting progress, per-asset errors, and allowing cancel. V3 gets the same capability as a first-class job: a `label_generation_runs` queue processed by a `label-worker` process (System → Processes heartbeat, pause-aware), results stored in `generated_labels` (the table the earlier labels spec reserved for this phase), a Generate Labels page at `/labels/generate` in the portal's house style, and API endpoints any other surface can call to enqueue a run.

## V2 inventory (all preserved unless listed under "Deliberate differences")

- Page: move picker (hides completed/archived moves; newest first) with a summary (project/status/asset count); multi-select of label types Front / Top / Rail / Custom with descriptions; Generate button (disabled until a move and ≥1 type), Cancel while running (stops after the current batch); progress bar `processed/total` with the current asset; a status log (newest first, capped at 100, per-entry icon/timestamp/counts) with Clear; an "N Errors Occurred" panel with a summary by error type and a sample table (asset / type / message) plus a note about how many are not shown; alerts for start/complete/fail/cancel.
- Job: one type per job, types processed sequentially by the page; template lookup by type — `top` prefers a template assigned to the move's destination site, else the generic "Top Asset Tag"; other types by fixed name; no template → job fails "Template for 'X' not found or not active" (custom may have no template → empty label). Per asset: skip when a label of that type exists and `overwrite` is false; substitute placeholder values (asset id, name, serial, make/model, source/destination raw + RU + site names, move name/date); a template's `label_generation_code` may split `destination_raw`/`source_raw` by `.` into named tokens by position and enforce per-field length limits; unresolved tokens become empty; the label is stored on the move-asset row (`label_info.{type}_label` + `generated_at`); batches of 200; counters generated/skipped/errors/processed; error details (first N) with a summary by type; one active job per move (409); jobs older than an hour are dropped from memory.

## V3 design

### Data (migration 0055, `down_revision = "0054"`)

- `label_generation_runs`: `id` uuid pk, `initiative_id` FK initiatives (NOT NULL), `label_types text[]` (vocab `type` keys, ≥1), `regenerate_existing bool` (V2 `overwrite`; default false), `status` (`queued|running|completed|failed|canceled` — American spelling), `cancel_requested bool default false`, `current_label_type text null`, `current_item text null`, counters `total int, processed int, generated int, skipped int, errors int` (default 0), `error_summary jsonb default '{}'` (error type → count), `error_details jsonb default '[]'` (first 50 `{item, label_type, type, message}`), `error text null` (run-level failure), `requested_by` FK people, `notify bool default false`, `created_at, started_at, finished_at`, `worker_id text null`. Index on `(initiative_id, created_at desc)`; partial unique index enforcing ONE active run per initiative (`status in ('queued','running')`).
- `generated_labels`: `id` uuid pk, `entity_type text` (`asset|container`), `entity_id uuid`, `initiative_id` FK (nullable — a label may outlive an initiative), `label_type text`, `template_id` FK label_templates, `template_version int`, `language_key text`, `dpi_key text`, `size_key text`, `code text` (compiled, ready to print), `values jsonb` (the substituted placeholder values, for audit/preview), `run_id` FK runs (nullable), `generated_at`, `stale bool default false`. Unique `(entity_type, entity_id, initiative_id, label_type)` — regenerating replaces the row (upsert).
- `label_templates.generation_rules jsonb default '{}'`: V2's `label_generation_code` port — `{"destination": {"1": "nap", "2": "row"}, "source": {...}, "length_limits": {"asset_name": 20}}`. Position maps split the raw location on `.` (1-based) into extra tokens; length limits truncate named values. Validated on template create/PATCH (keys must be token-shaped `[a-z0-9_]+`, positions positive ints, limits positive ints).

### Worker `label-worker` (`api/src/serversherpa/labels/generate/`)

- `worker.py`: mirrors `reports/worker.py` — `run_forever(poll_seconds)` with `start_heartbeat("label-worker", "worker")`, `poll_workers_paused` pause, startup + periodic stale-run sweep (`running` older than 15 min with no worker heartbeat → back to `queued`), `run_once` claims with `FOR UPDATE SKIP LOCKED` (reuse the `reports/jobs.py` shape, generalized or duplicated for this table), `db_logging.install("label-worker")`. CLI `serversherpa label-worker [--poll-seconds] [--once] [--reload]` (copy of `report_worker`), Procfile.dev line `labelsvc: api/.venv/bin/serversherpa label-worker --reload`, System → Processes shows it by the heartbeat name.
- `runner.py` `process_run(db, run, *, sessionmaker)`: load initiative (+ client, origin/destination sites), roster `InitiativeAsset`+`Asset`+`AssetModel` ordered by `Asset.legacy_id`; `total = len(roster) × len(label_types)`; for each label type in order: resolve the template (`select.py`) — none → record a run-level error for that type (`no_template:{type}`) in `error_summary`, count every asset of that type as an error with message "No active template for {type}", continue with the next type (V2 failed the whole job; V3 keeps going so the other types still generate — deliberate); for each asset: cancel check (per batch of 200 → `canceled`, counters kept); existing current label (same template id + version, not stale) and `regenerate_existing` false → `skipped`; else build values (`values.py`), compile (`engine.py`), upsert `generated_labels`, `generated += 1`; exceptions → `errors += 1`, summary/details (first 50); `processed += 1`; `current_label_type`/`current_item` updated per batch; counters flushed per batch so the page can poll. Finish `completed` (or `canceled`/`failed`), `finished_at`; inbox notification when `notify` (`labels_ready` / `labels_failed` kinds with a link to `/labels/generate?run=<id>`).
- `select.py` `select_template(db, label_type, site_id) -> LabelTemplate | None`: active templates of that type; prefer one linked to `site_id` (the initiative's destination site, else origin), else a GLOBAL one (no site links); ties → highest `version`, then newest `updated_at`. Templates linked only to other sites are never used.
- `values.py` `placeholder_values(asset_row, initiative, sites, catalog_keys) -> dict[str,str]`: every catalog key that applies: `asset_id` (`legacy_id`), `asset_name`, `serial_number`, `make`, `model`, `make_model`, `source_raw` (`source_position` if set else `source_rack`), `source_ru` (`U{int}` when integral else `U{n}`; empty when None), `source_site`, `destination_raw`, `destination_ru`, `destination_site`, `move_name`, `move_date` (`%m/%d/%Y` of `scheduled_start` in the report time zone; empty when unscheduled), plus `container_name`/`container_id` empty for assets; then `generation_rules` position tokens and length limits. Missing data → `""` (V2 parity). Unknown template tokens → `""` (already the compiler/`apply_placeholders` rule) and are counted once per run in `error_summary` under `unknown_token:{key}` WITHOUT failing the label (deliberate: V2 silently blanked them).
- `engine.py` `render_label(template, values, vocab) -> str`: `code` kind → `apply_placeholders(template.code, values)`; `design` kind → the same compile path as `routes/labels._compile_design` (extract the vocab-lookup-free core into `labels/compile.py` so both the route and the worker call one function with `size/dpi/language` meta already resolved).

### API (`api/routes/labels.py`, resource `labels`: view to read and to start/cancel — V2 required only portal access; change to `labels:change` later if abuse appears)

- `POST /labels/generate/runs` `{initiative_id, label_types: [..], regenerate_existing?: false, notify?: false}` → 202 `LabelRunOut`; 404 `initiative_not_found` (scope-checked like reports), 422 `invalid_label_types` (unknown/inactive keys or empty), 409 `run_active` when the initiative already has a queued/running run (payload includes `run_id`).
- `GET /labels/generate/runs?initiative_id=&limit=` (newest first, default 25) and `GET /labels/generate/runs/{id}` → `LabelRunOut` (all columns + `initiative_name`, `requested_by_name`, `progress_pct`).
- `POST /labels/generate/runs/{id}/cancel` → sets `cancel_requested` on a queued/running run (a queued run flips straight to `canceled`); 409 otherwise.
- `GET /labels/generate/preview?initiative_id=` → `{initiative: {id, name, client_name, status, scheduled_start, source_name, destination_name, asset_count}, types: [{key, label, template: {id, name, version, scope: 'site'|'global'} | null, current: <assets with a current label>, stale: <count>}], active_run_id}`.
- `GET /labels/generated?initiative_id=&label_type=&entity_id=&limit=&cursor=` → rows (id, entity_type, entity_id, asset_id/serial/name for assets, label_type, template name/version, generated_at, stale, code) — the building block the future Print page and other callers use.
- Template create/PATCH accept `generation_rules`; `LabelTemplateOut` returns it. The V2 import script also maps `label_generation_code` → `generation_rules` when present (dry-run safe).

### Portal `/labels/generate` (page, house style; roomy header like the report modals)

- Header: eyebrow "Labels", title "Generate Labels", description "Generate printable labels for every asset on an initiative. Labels are rendered by the label worker and kept for printing."
- Two-column layout (`OptionsGrid`-style): **left** — Initiative picker (ComboBox over initiatives whose status is not completed/canceled/archived, newest first) with the shared `InitiativeSummary` preview card underneath plus the preview endpoint's asset count and, per type, the resolved template chip ("Top asset tag v5 · site" / "global" / "No active template" in `c-red`) and "N current · M stale" counts; **right** — **Label types** as `ChoiceCard`-style multi-select cards (one per active vocab `type`, checkbox semantics `role="checkbox"`, description from the vocab label/meta, disabled with hint when no template resolves), **Options** group: Switch "Regenerate existing labels" (hint: "Off skips assets that already have a current label for the type"), Switch "Notify me when finished"; **Generate labels** button (disabled until initiative + ≥1 type; disabled with hint while a run is active for that initiative) and **Cancel** while running.
- **Progress** panel (visible while a run is active): status chip, "Processing Top Label · 412 / 1,240" with a progress bar, current item, live counters generated / skipped / errors; polls `GET …/runs/{id}` every 1.5 s.
- **Recent runs** list (standard directory list) for the selected initiative (or all when none): started, initiative, types (chips), status chip, generated / skipped / errors, requester; row action "View errors" opens an **Errors modal** (roomy header pattern: eyebrow "Generate Labels", title "N errors in <initiative>", description) with the summary-by-type chips and the sample table (item / type / message, first 50) and the "only the first 50 are shown" note; deep link `?run=<id>` opens that run's errors/progress.
- Template editor gains a compact **Generation rules** panel (position → token rows for destination and source, length limits rows) saved through the template PATCH.

## Deliberate differences from V2

- Runs are DB rows processed by a separate worker (survive restarts; one worker can be scaled; callable from any surface); one run covers several label types.
- A missing template fails only that type, not the whole run.
- Labels live in `generated_labels` (per entity/type, template-versioned, `stale` flag) instead of JSON on the roster row; `InitiativeAsset.label_info` is left untouched (legacy V2 import data).
- Template selection uses V3 site links for every type (V2 only for `top`); "Custom" type without a template is an error rather than an empty label.
- Unknown tokens are reported in the run's error summary instead of silently blanked.
- Runs are kept (history list) instead of an in-memory dict pruned after an hour.

## Out of scope

Print Labels page (IndexedDB cache, printers), container label generation (table supports it; runner handles assets only for now), automatic regeneration when watched data changes (the `stale` flag is set only by explicit regeneration in this phase), images in templates.

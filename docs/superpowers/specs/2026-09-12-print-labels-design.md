# Print Labels — V3 port of V2's `/labels/print` (WebUSB Zebra printing + offline label cache)

**Date:** 2026-09-12 · **Status:** approved (Jimmy, 2026-09-12: all V2 functionality and options retained, V2 layout and flow mimicked in V3 UI, WebUSB connection, everything in the Print Settings modal, new modals dynamically sized with the roomy header; offline cache included; settings persist per browser; label types from the vocabulary plus Custom ZPL) · **Branch:** `print-labels`

## What V2 does (all preserved)

Page `portal-v2/src/pages/PrintLabels.jsx` (1,610 lines, last touched 2026-08-04 — the newest of the three reference copies):

- **Header**: back link, printer icon, title "Print Labels", hint "Select a move and template to print asset labels", and a gear button for Print Settings that is tinted amber when any setting differs from its default. A dismissible status alert (success / info / warning / error) sits under the header.
- **Three cards in a row**: **1. Select Move** (dropdown; finished/archived/historical moves hidden, newest first; summary box with project, status, asset count) · **2. Select Label Type** (Front / Top / Rail / Custom; description under it; Custom reveals a 6-row monospace "Raw ZPL Code" box) · **3. Connect Printer** (green/red dot, "Connect via USB" → `navigator.usb.requestDevice({filters:[{vendorId: 0x0A5F}]})`, open, `selectConfiguration(1)` when none, `claimInterface(0)`; "Disconnect Printer" releases interface 0 and closes without `forget()`; hint "Requires a Zebra printer connected via USB. Make sure the printer is turned on before connecting."). A `disconnect` USB event for the claimed device drops the connection with a warning; leaving the page releases and closes the device.
- **4. Select Assets to Print**: search box (name, serial, make, model), refresh button, sticky-header table with a checkbox column (header checkbox = select all *filtered* rows, indeterminate when partial; row click toggles), columns ID / Asset Name / Serial Number / Make / Model / Source Rack / Source RU / Status chip, Excel-style per-column sort + text filter + distinct-value checkbox filter (`columnFilters.jsx`); sorting by Source Rack orders RU top-down within a rack; column filters are cleared when the move changes; footer "Showing N of M assets".
- **Ready to Print** bar: "N label(s) will be printed", three summary chips (Move Selected / Label Type Selected / Printer Ready), a second gear button, and the green "Print N Label(s)" button (disabled without printer, type, or selection).
- **Printing**: validation (custom needs ZPL text; otherwise every selected asset must have `label_info[<type>_label]`, else "N selected asset(s) do not have Front Label data. Please generate labels first."). Order = displayed (sorted/filtered) order of the selected rows, or with **Print by Rack** on: rack ascending (numeric-aware) then RU descending. Each label's ZPL is transformed: horizontal offset → `^LS<-offset>` (replace an existing `^LS` or insert after `^XA`) and, when positive, `^PW` widened by the offset; vertical offset → `^LT<offset>` after `^XA`; copies > 1 → `^PQ<n>` before `^XZ` (not for blanks or the alignment test). Bytes go to the first bulk OUT endpoint with a 100 ms pause between labels. When the rack changes (also across a batch boundary), `blanksBetweenRacks` blank labels (`^XA^FO10,10^A0N,10,10^FD ^FS^PQ<n>^XZ`) are fed first. Up to `batchSize` labels print inline ("Printing N label(s)…" → success / "Printed N, skipped M (no label data)"); more opens the **batch dialog**.
- **Batch dialog** (non-dismissable while printing): "X of N labels printed", progress bar (green when done), Current Batch / Total Batches / Per Batch figures, "Auto print next batch (5s delay)" switch (a finished batch starts the next after a 5-second countdown; turning the switch off cancels), status lines ("Printing batch i of n…", "Batch i sent - waiting for printer to finish printing…", "Batch i complete! Ready to print next batch." / "…starts automatically in Ns…", "All N labels printed successfully!"), buttons Cancel / Reprint Current Batch / Print Next Batch (k labels) / Done. After a batch is sent, the page polls the printer's `~HS` host status (2 s read timeout, drains up to 3 further packets at 250 ms, field 5 of STX-string 1 = formats queued) once a second until the queue is empty, updating the live printed count (sent − queued), with a deadline of max(30 s, 3 s × labels) and a fallback sleep of 0.5 s × labels when status is unreadable.
- **Print Settings dialog**: Vertical Offset (dots, + moves down), Horizontal Offset (dots, + moves right), Copies (min 1), Batch Size (min 1, default 50), Print by Rack switch with "Blanks Between Racks" (min 0, default 1, disabled when the switch is off), and **Print Alignment Test Label**: concentric boxes 25 dots apart (outer box 5 dots in at 4-dot thickness, inner boxes 2-dot) with the text `ALIGN <size> 300DPI` centered; buttons "1×2 Label" (600 × 300 dots) and "2×4 Label" (1200 × 600 dots), gated on a connected printer; current offsets applied, copies ignored. Footer Reset (disabled when unmodified) / Done. Settings live in page state only.

## V3 design

### Approach

Page-scoped port: the printer connection lives for the page (released on leave, as V2) but the transport is a pure module + hook so the Printers page can reuse it later. No app-wide printer session, no server-mediated printing.

### Data sources (all existing except one endpoint)

- Initiatives: `listInitiatives()` filtered by `visibleInitiativesForGenerate` (`lib/generateLabels.ts` — hides `completed`/`cancelled`, V2's "finished moves hidden"), newest first.
- Roster: `GET /initiatives/{id}/assets` (`listInitiativeAssets`) — `asset.legacy_id` (Asset ID), `asset.name`, `asset.serial_number`, `asset.model_make`, `asset.model_name`, `source_rack`, `source_ru`, `status_label`/`status_color`.
- Label types: `listLabelVocab('type')` active rows, in vocab order, plus a synthetic **Custom** entry. Sizes and DPI vocab feed the alignment test. *(Updated 2026-09-16: originally these were the active rows **minus** `CONTAINER_LABEL_TYPES`, behind an `isAssetLabelType` helper. Container labels phase two deleted that helper and put the container types on the page — picking one switches the page to container mode, listing the initiative's containers instead of its assets. `isContainerLabelType` in `lib/labels.ts` is what chooses the mode.)*
- Labels: **new** `GET /labels/generated/bundle?initiative_id=<uuid>&label_type=<key>` (`labels:view`, same initiative scoping as `list_generated_labels`) → `{ initiative_id, label_type, fetched_at, labels: [{ id, entity_type, entity_id, template_id, template_name, template_version, language_key, size_key, dpi_key, stale, generated_at, code }] }` — every generated label for that pair (`entity_type = 'asset'`), no paging (an initiative's labels are bounded by its roster; 5,000 × ~1 KB is fine). Unknown type or initiative → empty list (404 `initiative_not_found` only when the initiative is out of scope/missing, matching the preview endpoint). `GeneratedLabelOut` is untouched.

### Portal code shape

- `portal/src/labels/zebraUsb.ts` — pure transport over a `UsbDeviceLike` interface (`opened`, `configuration`, `productName`, `open/close/selectConfiguration/claimInterface/releaseInterface/transferOut/transferIn`) so tests use a fake: `ZEBRA_VENDOR_ID = 0x0a5f`, `requestZebraDevice(usb)`, `openPrinter(device)` (V2's close-if-open → open → selectConfiguration(1) when null → claimInterface(0)), `closePrinter(device)` (release then close, both tolerant), `ensureOpen(device)` (V2's reopen-on-stale path; throws "Printer connection lost. Please reconnect." when it fails), `findBulkEndpoints(device)`, `sendRaw(device, text)` ("Could not find printer output endpoint" when no OUT), `queryQueuedFormats(device, {timeout})` (`~HS`, 2 s / 250 ms drain, returns number | null), `waitForPrinterIdle(device, labelsSent, {onQueued, sleep, now})` (V2's deadline/fallback semantics, injectable clock), `parseHostStatusQueued(text)`.
- `portal/src/hooks/useZebraPrinter.ts` — `{ supported, connected, productName, status, connect, disconnect, send(zpl), queryQueued, waitForIdle }`; `supported = typeof navigator !== 'undefined' && 'usb' in navigator`; subscribes to `navigator.usb` `disconnect` for the held device (drops state with a warning), keeps a ref for the unmount release, and surfaces V2's success/info/warning/error messages through a `status` value the page renders as the notice.
- `portal/src/lib/printLabels.ts` — pure helpers: `PrintSettings`, `DEFAULT_PRINT_SETTINGS` (`verticalOffset 0, horizontalOffset 0, copies 1, batchSize 50, printByRack false, blanksBetweenRacks 1`), `settingsModified`, `clampSetting(field, raw)` (copies/batchSize ≥ 1, blanks ≥ 0, offsets any integer; upper bounds 99 / 500 / 20 enforced on blur and before use), `readPrintSettings()/writePrintSettings()` (localStorage key `labels.print.settings`, try/catch, unknown keys dropped, values clamped), `applyPrintSettings(zpl, settings, {singleCopy})` (V2's exact `^LS`/`^PW`/`^LT`/`^PQ` transform), `blankLabelsZpl(n)`, `alignmentTestZpl(widthDots, heightDots, sizeLabel, dpi)` (V2's boxes; the text reads `ALIGN 4x2 300DPI`), `printOrder(selectedIds, displayedRows, settings)`, `batchBounds(batchNumber, batchSize, total)`, `labelStatusFor(row, bundle)` → `'ready' | 'stale' | 'missing' | 'unsupported'` (unsupported = `language_key !== 'zpl'`), `missingLabelIds(selectedIds, bundle)`, `LABEL_TYPE_CUSTOM = 'custom'`.
- `portal/src/lib/labelCache.ts` — typed IndexedDB wrapper (no dependency; database `basecamp-labels` v1): store `initiatives` keyed by initiative id → `{ initiative: InitiativeItem, roster: InitiativeAssetRow[], cached_at }`; store `bundles` keyed `${initiativeId}:${labelType}` → the bundle payload plus `initiative_name`, `cached_at`. API: `putInitiative`, `getInitiative`, `listInitiatives`, `putBundle`, `getBundle`, `listBundles`, `listBundleSummaries` (summaries only, no label codes, for state that must not pin ZPL text), `deleteBundle`, `deleteInitiative` (with its bundles), `clearAll`; every call resolves to `null`/no-op when IndexedDB is unavailable (private mode, jsdom) so the page never depends on it.
- `portal/src/lib/api.ts` — `GeneratedLabelBundle` types + `getGeneratedLabelBundle(initiativeId, labelType)`.
- `portal/src/pages/PrintLabels.tsx` (replaces the `Placeholder` at `/labels/print` in `App.tsx`), `portal/src/components/labels/PrintAssetList.tsx`, `PrintSettingsModal.tsx`, `PrintBatchModal.tsx`, `OfflineCacheModal.tsx`; styles appended to `portal/src/styles/labels.css` under a `plabels-` prefix (layout/color only — the list typography guardrail stays green; no raw `<table>`).

### Print flow

- Validation as V2 (messages verbatim), plus the notice offers **Deselect missing** when assets lack labels. Labels with `language_key !== 'zpl'` count as missing ("N selected asset(s) have labels compiled for a non-Zebra printer"). Stale labels print normally (they have code) with an info notice "N labels were generated with an older template — regenerate for the latest layout."
- Order via `printOrder` (screen order of selected rows, or rack/RU when Print by rack). ≤ `batchSize` → inline; otherwise `PrintBatchModal`. Sending, blanks, 100 ms pauses, `~HS` idle wait with live count, deadline and fallback: all V2 semantics through the transport module. Errors during a batch → "Batch i failed: <message>" and the modal's buttons re-enable.
- Alignment test: `alignmentTestZpl` for the chosen size × DPI, sent `singleCopy`, offsets applied.

### Offline mechanics

- Selecting an initiative fetches the roster and the initiative item; selecting a type fetches its bundle; each success is written to the cache (`putInitiative`/`putBundle`). A failed fetch (network error or non-OK) falls back to the cache for that key; when the cache has it the offline banner shows, otherwise the notice reports the error. `online`/`offline` window events re-run the fetch when connectivity returns.
- The initiative list falls back to cached initiatives when `listInitiatives` fails; the type list falls back to the vocabulary keys present in cached bundles (labels come from the cache, so the vocab request is not required).
- Auth: an unreachable API leaves the session in place (`refreshSession` swallows network errors; `apiFetch` only ends the session on 401), so an open page keeps printing. **Cold-start offline (reload with no network) is out of scope** — it needs an app-shell service worker and an offline-tolerant auth bootstrap.

### API

- `GET /labels/generated/bundle` in `api/src/serversherpa/api/routes/labels.py` next to `list_generated_labels`, reusing its scope condition; schema `GeneratedLabelBundleOut` / `GeneratedLabelBundleItemOut` in `schemas.py`. Ordered by `generated_at`, `id` for determinism.

## Deliberate differences from V2

- Label source is `generated_labels` (bundle endpoint) instead of `label_info` on the move asset; the list shows a Label status column and a Ready/Missing filter, and the missing-label error offers Deselect missing.
- Label types come from the vocabulary (Top, Front, Rail today) instead of a hardcoded list; Custom is kept.
- Print settings persist per browser (localStorage) instead of resetting on reload.
- The alignment test takes any size from the vocabulary at 203 or 300 DPI instead of two fixed buttons (the V2 pair is `2x1` and `4x2` at 300).
- Offline cache (automatic on every online load, plus the explicit Download and management modal).
- Browsers without WebUSB get an explanation instead of a failing button.

## Out of scope

Cold-start offline (service worker, offline auth); an app-wide printer session; Brother printers over USB (`escp`/`ptouch` labels are flagged unsupported); wiring the Printers page's "Test Label Alignment" row to these settings; printing container labels through this page.

## Implementation notes (2026-09-12)

- The hook actually lives at `portal/src/lib/useZebraPrinter.ts`, not `portal/src/hooks/useZebraPrinter.ts` as the "Portal code shape" section above says.
- Its exported `ZebraPrinter` interface returns `notice` (a `{ type, message } | null`), not `status`, and there is no separate `queryQueued` in the public return type — only `waitForIdle`.
- A stale count is reported as a suffix appended to the success notice (e.g. `". 3 used an older template — regenerate for the latest layout."`), not as the separate info notice described in "Print flow" above.
- `PrintBatchModal` has no close button at all while printing — no scrim-click-to-close, no X button; Escape only cancels between batches.
- Column filters, the Ready/Missing filter, and the search box now reset on initiative change via a `resetKey` prop on `PrintAssetList`, keyed on `initiativeId`.
- The `online` window-event refetch now keeps the current selection instead of clearing it, via a `keepSelection` option on `loadRoster`.
